# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status and direction

"Freedom Haters of SPLORR!!" (FHOS) is a satirical terminal game ("Live Free Or Die" is the joke). It is published on itch.io at https://thegrumpygamedev.itch.io/freedom-haters-of-splorr as native Windows/Linux/Mac builds (version 56, ~30 MB each; devlog posts: Errand Boy Missions, Air Scoops and Fuel Scoops, "When Do You Just Decide to Get It Out There"). The goal is a **browser build on an Odin -> `js_wasm32` stack** replacing the VB.NET/Spectre.Console terminal app. The author's wider direction (games are now vibe-coded with Claude, user is product owner/QA; old versions get removed as web versions replace them) is described in `/home/yermom/git/bok-of-splorr/splorr/Concepts/Metaphor design.md`, which is an additional working directory for this session. Keep that tone: minimal, retro/1-bit, short deadpan text, absurdist; keep the "of SPLORR!!" branding. Don't "fix" intentionally unfair mechanics. Publishing (`ship.sh` / `butler push`) changes the live page: only when asked.

The Odin toolchain skeleton exists (see "Odin / wasm stack" below); The existing VB.NET code is the reference implementation of the game design; treat it as the spec to port from, not as the shipping target. `README.md` doubles as the design notes (episode checklist, SIGMO-vs-anarchist factions, the "Rules", and the faction ASC model: Authority/Standards/Conviction axes 0–100, relationship = Euclidean distance, 0–25 Friendly, 26–50 Neutral, 51+ Hostile).

## Odin / wasm stack (the future)

Odin is at `/home/yermom/ODIN/odin` (not on PATH; `build.sh` finds it).

```bash
./build.sh     # runs `odin test game`, builds dist/ (game.wasm, odin.js copied from the same Odin install, html/css/js)
./serve.sh     # http://localhost:8000 serving dist/ (wasm needs http, not file://); restart it after build.sh, which recreates dist/
odin test game                                  # native tests; whole suite
odin test game -define:ODIN_TEST_NAMES=game.render_draws_foreground_and_background   # one test
./ship.sh      # zips dist/ and `butler push`es the html5 channel. Publishes: run only when asked.
```

- `game/` is one Odin package. Everything is platform-independent except `platform_js.odin` (`#+build js`), which exports `step(dt: f64)` (odin.js calls it every animation frame) and imports `js_next_key` / `js_present` from `web/game.js`. Test files carry `#+build !js` because `core:testing` doesn't compile for wasm.
- UI is a 40x25 `Text_Buffer` of colored characters rasterized by `render` into a 320x200 RGBA `Frame` using the 8x8 bitmap `font` (one u64 per glyph, generated from the ROM font in `~/git/odin-wasm-framebuffer`); JS blits it once per frame. New game logic should stay platform-independent and testable natively.
- Screens: `Screen` (in `screens.odin`) is a union of per-screen structs holding their own state. `screen_draw` / `screen_key` dispatch on it; `screen_key` returns a `Transition` (`Push`, `Replace`, `Pop`, or nil to stay) which `stack_apply` applies to the fixed-size `Screen_Stack` in `App`. `Reset` throws the whole stack away and starts over. Dispatchers (`screen_draw`, `screen_key`, `screen_tick`) pass a `^Session` (in `App`; `session.odin`) that owns the running `Generator` or the finished `Universe`; `app_tick` runs once per frame so a screen can do timed work (the Generate screen steps the generator within `GENERATION_BUDGET`). The seed comes from `Session.seed_source` (browser: `js_random_u32` -> `crypto.getRandomValues`; tests inject a fixed one). To add a screen: add its struct to the union, a draw proc and a key proc, and a case in the dispatchers. `menu.odin` has the shared cursor-menu helpers. The 8x8 font has no line gap, so menus and text use every other row.
- RNG (`rng.odin`): `Rng` is splitmix64, deliberately not `core:math/rand`, so a seed means the same universe forever (`sequence_is_pinned` guards this; changing the algorithm invalidates saves). All randomness goes through an `^Rng` passed in, never a global. Dice notation is the VB's (`"10d11+-10d1"`, `"12d6/6"`, `"1d6*10"`): `dice_parse` returns ok, `dice_roll` asserts on a bad literal, `dice_bounds` gives exact min/max for tests.
- Data model (`universe.odin`, `world_types.odin`): `Universe` owns dynamic arrays of Faction, Star_System, Planet, Satellite, Map and Actor, addressed by distinct 1-based ids (0 = none). Maps are sparse: a `Map` is a kind (fixed size in `map_sizes`), its owning actor, and the actors on it; any cell no actor covers is empty. An `Actor` has a center `pos`, an odd `size` footprint (planets 3x3 / 5x5, satellites 3x3), and an `interior` map that stepping into it leads to, so places nest galaxy > star system > planet vicinity > planet orbit. Names are fixed 32-byte `Name`s. Type tables (`planet_info`, `star_info`, ...) carry the VB descriptor data. `Hue` has CGA colors plus Orange/Pink/Tan because planet types need them.
- Generation (`generator.odin`, `name_generator.odin`): `generator_start(seed, settings)` then call `generator_step` once per frame until it returns false (`generator_current` / `generator_steps_remaining` feed a progress screen), then `generator_finish` hands over the `Universe`. Steps follow the VB queue: Factions, Galaxy, every Star_System, every Planet (satellites included), Factionize, Avatar. Placement is rejection sampling with `find_spot`. Not yet generated: nexus/wormholes, stations, debris, military ships. Deliberate deviation: planets and satellites are placed in `1..size-2` (the VB used `1..size-3`, which looked like an off-by-one).
- Play (`play.odin`, `map_view.odin`, `play_screens.odin`): `play.odin` holds the movement/interaction rules with no screen code (`avatar_move`, `avatar_interact`, `avatar_signal_distress`), tested directly. Every move attempt costs a turn, 1 oxygen and 1 fuel; with no fuel you can't move (Signal Distress in the action menu is the VB's emergency refuel, 1 jool per fuel); bumping an actor or a map's border sets `avatar.bumped` and the Navigation screen pushes an `Interaction_Screen`. Going into an interior (`Approach`, `Enter_Orbit`) costs a turn and oxygen and lands just inside the border; leaving is free and lands beside the owner's footprint. Refilling: every planet orbit has one `Star_Dock` (added in `step_planet`); bumping it offers Refill Oxygen (1 jool per 10, rounded up) and Refuel (1 jool per 3) when the tank isn't full, with the price in the menu label. `Planet_Body` offers a free Gather Atmosphere only if `avatar.accessories` has the Atmospheric Concentrator AND the planet type is breathable (`planet_info[..].can_refill_oxygen`; in the VB that flag is never read and the concentrator works on any planet, so this is a deliberate departure). Nothing grants the concentrator yet (5,000 jools in the live game, awaiting the shop). The border arrows are computed (`map_is_edge`), not stored. Game over (dead or bankrupt) is noticed by `navigation_tick`. The font is CP437: stars are 0x0F, planet bodies 0xB2, satellite bodies 0xB1, ship = a triangle for its facing.
- Touch pad: `web/index.html` has a d-pad and Esc/Enter buttons; `web/game.js` (`wirePad`) pushes the same key codes into the key queue, so the game is unaware of it. It shows on `pointer: coarse` screens, after any touch, or with `?pad` in the URL.
- Items and debris (`items.odin`): items are individual `Item` records in `Universe.items`, held by id in `avatar.inventory`; `item_info` carries the VB's names/prices/offers/tech levels (marked kinds, Fuel_Supply and Life_Support, scale with `mark`). `inventory_stacks` groups by kind+mark for display. Marked kinds are named with roman numerals as in the VB ("StarLume Fuel Mark II"). `item_description` returns the VB's paragraphs for every kind (ASCII only: the CP437 font has no em-dash or curly quotes) and `item_stats` the tech level / capacity lines; the item page wraps and scrolls them (`page_lines`). Debris is an `Actor` (`kind = .Debris`) holding a `loot` count, 12d6/6 piles per star system (`add_debris`); salvaging (`avatar_salvage`) is free, turns `loot` into scrap items, and takes the pile off its map with `actor_remove` (the actor id stays valid but `map_id` is 0, so anything iterating `u.actors` should skip those). `menu_draw` scrolls long lists; `text_put_wrapped` wraps text.
- Trading (`trade.odin` rules, `trade_screens.odin` screens): every planet orbit has 1-2 `Trading_Post`s (max(1, 3d6/8)). A post sells tank and rod always, the concentrator at planet tech level >= 3, the fuel scoop at >= 7, and Mark N life support/fuel supply at tech level >= N, all at fixed prices; it buys only scrap (1 jool each). Flow: Interaction `Trade` -> `Trader` -> `Buy_List`/`Sell_List` -> `Quantity` (One / Maximum or All / Half / Specific) -> optional `Number_Entry` (up/down 1, left/right 10, typed digits; the touch pad can't type digits) -> `Confirm_Trade`, which pops back to the list with `Pop_Count`. Oxygen tanks (+100, leave a scrap) and fuel rods (+100) are used from their item page; a tank is also used automatically when a turn would take the last oxygen (`avatar_auto_use_tank`; the Navigation screen reports it once via `avatar.auto_used`).
- Equipment and the shipyard (`equipment.odin` rules, `shipyard_screens.odin` screens): the ship has four slots (`Equip_Slot`: Life Support and Fuel Supply are mandatory, Accessory(0)/(1) are optional) holding item ids in `avatar.equipment`; the ship starts with Mark I life support and fuel supply installed, and `avatar.fuel`/`oxygen` capacity and level come from them. Each supply unit remembers its own level (`Item.level`): `unequip_item` saves the tank level and zeroes the tank, `equip_item` fills the tank to the new unit's level, so installing a fresh unit is a refill (kept from the VB on purpose). `shipyard_change` charges the old unit's uninstall fee plus the new unit's install fee up front and refuses if the yard's planet tech level is below either unit's tech level (life support Marks I-V need 1/3/5/7/9, fuel supplies need their mark). Shipyards appear on about one orbit in four (1d4/4). Free planet oxygen needs the concentrator installed (`avatar_has_equipped`); the fuel scoop gives free fuel when you bump a star. `Equipment_Screen` (action menu) is read-only; `Shipyard_Screen` -> `Slot_Items` is the single slot list that replaces the VB's three menus. `menu_draw` can take a `details` list for a second line under each entry.
- Delivery missions and reputation (`mission.odin` rules, `mission_screens.odin` screens): every star dock holds one `Delivery` item to offer (`Actor.offer`), generated by the `Step_Missions` generator step after factions are assigned, bound for another planet of the same faction (a faction with one planet offers nothing; the VB crashed). A `Mission` (origin, destination, reward 5d20, word-table indexes for the item name and recipient) lives on the `Item`. Reputation is an int on `Planet`, `Star_System` and `Faction` (start 100 for SIGMO, the home planet and the home system, else 0); you may carry 1 + worst/25 deliveries (worst of the dock's planet, system and faction), a negative worst standing needs a deposit of half the reward and allows one, completing gives +1 to each distinct group at both ends, abandoning -5. Destinations are shown as the planet's star system and its galaxy position because the pedia that the live game uses to look planets up is not ported. Each delivery is its own inventory row (`Item_Stack.item`); its item page has Abandon Mission. The action menu is Status, Inventory, Equipment, (Signal Distress), Cancel.
- SPLORRPedia (`pedia.odin` data, `pedia_pages.odin` page text, `pedia_screens.odin` screens, `relations.odin`): the action menu's SPLORRPedia lists factions, star systems, planets and satellites (the whole galaxy, from the start, as in the live game), sorted by name via `Universe.pedia` (built when generation finishes). Lists take a typed filter (any printable key; Backspace edits) and Left/Right jump between first letters for the touch pad; scoped lists (a faction's planets, a system's planets/satellites/factions, a planet's satellites) come from `pedia_entries`. Pages are built only in `pedia_page_doc` so a future 'out of date / propagandized pedia' (see PORT_PLAN.md) can sit between the truth and the page. Lists and pages allocate from the temp allocator, which `app_key`/`app_tick` free. Faction relations (`relation_between`) use the TRUE Euclidean distance (the live game's misplaced square root is deliberately not ported) with the README thresholds, so every generated faction is Hostile to SIGMO (a test keeps that satire true). The browser test tool's `type` action sends no key-down events, so use `key` with space-separated keys to type into pedia filters.
- Save/load (`save.odin` format, `storage.odin` slots, `save_screens.odin` screens): `universe_to_bytes` / `universe_from_bytes` walk the data types by reflection and write varints, behind a header of magic, format byte and a hash of the type layout, so a save from a build with different types is refused (`Other_Version`) instead of misread. Fields tagged `save:"-"` (`Universe.pedia`, `Avatar.bumped`, `Avatar.auto_used`) are not stored; the pedia is rebuilt on load. The reader validates enums, counts, union tags and ids (`universe_valid`) and a fuzz test corrupts saves to prove it never crashes. Adding or changing a field in the universe types changes the layout hash and orphans old saves, which is acceptable pre-launch; bump `SAVE_FORMAT` if you change the encoding itself. `Storage` is four function pointers (size/read/write/remove) in `Session.storage`: the browser backs it with localStorage (base64; `js_storage_*` in `platform_js.odin` and `web/game.js`), tests with `memory_storage()` (thread-local; call `memory_storage_reset()` first; `start_generating` does). Slot 0 is the Scum Slot, 1-5 are named; each has a "Turn N, J jools" note under a `.info` key. Game menu: Continue, Scum Save, Save, Scum Load, Abandon. Loading resets the stack to Main_Menu with Navigation on top (`Reset.on_top`); messages that follow a save pop first via `Pop_Then`. The Embark settings persist under `fhos.embark`. Dying leaves saves alone; export/import is deferred.
- Nexus, wormholes and star gates (`step_nexus` in `generator.odin`, rules at the end of `play.odin`, `travel_screens.odin`): the Nexus (`Universe.nexus`, a 63x63 `Map_Kind.Nexus` with no owner, so its border is not an exit) holds wormholes spaced by the density's `minimum_wormhole_distance`; each is paired (`Actor.target`, both ends) with a new wormhole on a random star system's map, which is the only way in or out (in the VB nothing led to the nexus). Wormholes are magenta circles; `Star_System.wormhole_count` feeds the pedia page. Entering a wormhole or star gate is free beyond the bump that reached it and lands on a random open cell beside the far end (`avatar_travel_to`; "Destination blocked!" if none). Star gates sit on about one planet orbit in four; `Star_Gate_Screen` lists the avatar's faction's other gates (the live game lets you use any gate to reach your own faction's gates, kept).
- Military ships (`step_fleet`): `fleet_size` = one per five star systems, on open galaxy cells (a new game starts at least `SAFE_START_DISTANCE` = 10 cells from every ship), each belonging to the faction of a random planet (its `Actor.planet` is home, `Actor.faction`). `patrol.odin` moves them: `navigation_tick` calls `patrol_catch_up` whenever `Universe.turn` passes `patrol_turn`, so every turn (a move, going into orbit) moves each ship one step (a chasing ship steps toward you within `SIGHT_RANGE`, else it wanders and drifts back inside `LEASH` of its home system). `ship_disposition` is the faction relation moved by reputation (25+ calms a step, 75+ another, -25 angers). A ship next to you (diagonals count, not calm) makes `patrol_contact`: friendlier ones hail (a Message), hostile ones open `Contact_Screen` (Pay Fine: a tenth of your jools, between 10 and `FINE_CAP` (50), never to bankruptcy; Hand Over Cargo: half the non-delivery items; no Escape), or just warn if you have nothing to take. Either way the ship then leaves you alone for `CALM_AFTER_*` turns (300 after a fine or seizure, 30 after a hail). Resist (offered only with a weapon installed) opens `Combat_Screen`, and bumping a ship with a weapon offers Attack. The system pedia page also lists shipyard / trading post / star gate / scrap / visit counts.
- Combat (`combat.odin` rules, `Combat_Screen` in `patrol_screens.odin`): rounds of Fire (needs a laser, 6+8/mark damage), Evade (halves the hit), Flee (10 fuel, one chance in two) or Surrender (back to the shakedown). A ship's hull is 60 + 10 per home-planet tech level and its attack 6 + 2 per tech level + 1d4. The shield soaks first and starts every fight full; the killing blow gets no reply. Win: the ship is removed, a debris pile of 6d6 scrap is left on the galaxy map, 2-4 (+ tech/4) Ship Parts (30 jools each at a trader) go into your hold and half the time 3-8 Weapons or Machinery into your cargo, its faction and home planet lose 5 reputation, factions hostile to it gain 1. Lose (hull 0): robbed and towed (`combat_defeat`: keep a quarter of the jools but never go bankrupt, lose three quarters of the non-delivery items, oxygen and fuel cut to 10, hull to a tenth, set down beside the home planet's star dock). `patrol_step` replaces a lost ship every `RESPAWN_EVERY` (100) turns while the fleet is under strength, out of sight.
- Combat gear and hull (`items.odin`, `equipment.odin`; new in the port): the ship has seven slots, the four older ones plus Weapon (Pulse Laser), Shield (Deflector Shield) and Armour (Armour Plating), each marked I-V and sold by trading posts by tech level (laser 2x mark, shield 2x mark - 1, plating mark). `weapon_damage` (8 + 6 per mark), `shield_capacity` (20 per mark, soaked per fight) and `armour_hull` (50 per mark) are the numbers `combat.odin` uses; gear price is base x mark squared (Mark I about 100, Mark V 2,500). `Avatar.hull` is a `Store` with maximum `BASE_HULL` (100) plus plating (`avatar_refresh_hull`); installing plating does not mend, removing it clamps the current hull. The shipyard screen's Repair Hull (`shipyard_repair`, 1 jool per 2 hull) is the only repair. Status and the map panel show the hull. Nothing damages the hull yet.
- Trade goods (`goods.odin` rules, `goods_screens.odin` screens; new in the port): eleven `Good`s (Metal, Oxygen, Fuel, Food, Textiles, Machinery, Medicine, Hype, Gems, Narcotics, Weapons) held as `Avatar.cargo` counts. Each planet has a `Planet.market` of `Price_State` (drift, pressure) per good, shared by its trading posts. Prices are in tenths of a jool (`tenths_text` prints "5.3"): `unit_tenths` = base price x planet type x tech level x values (the combined opinion compressed to 70-150%, half of its raw swing) x (1000 + 10 x drift + 4 per unit of net pressure, capped at +-50%)/1000, then the mode's percentage (you buy at +8%, sell at -8%, and what a faction charges you also follows your standing with it; black markets differ). A bulk trade is priced a unit at a time (slippage: each unit moves the price 0.3%) and only the total is rounded once (`quote_buy` / `quote_sell`); buying pushes the pressure up and selling down (it fades 25% per tick), and every `DRIFT_EVERY` (50) turns the drift random-walks within 15% (`markets_catch_up`, called from `navigation_tick`, capped so a loaded game does not replay ages). Cargo weighs (`good_info[..].weight`): every move burns an extra weight/50 fuel, the fraction carried in `Avatar.fuel_carry` (`cargo_fuel_for_move`, applied in `avatar_move`, never below empty); losing a fight costs three quarters of the cargo. Trader -> Trade Goods -> `Market_Screen` -> `Good_Trade` (buy/sell 1, 10, most/all). Law, contraband, infamy and black markets are the next two steps (PORT_PLAN.md).
- Law and infamy (`law.odin`, `Search_Screen` in `patrol_screens.odin`; new in the port): `faction_bans` derives a faction's banned goods from its values and ASC (SIGMO fixed: Narcotics, Weapons, Gems; high Authority bans Narcotics, then Weapons unless it values Martial Honor or Sovereign Freedom; Sustainable Harmony bans both; low-Standards Collective Prosperity bans Gems). A banned good cannot be bought or sold at that faction's planets (the market shows "banned"); the pedia faction page lists the bans. A patrol that is not Friendly and finds goods its faction bans aboard opens `Search_Screen` instead of a hail or shakedown (Hand Over The Goods: all contraband gone, +2 infamy; Pay The Fine: twice the goods' base value, keep them, +3; Resist (weapon only): combat, which also sets Surrender back to a search via `contact_screen_for`). `Avatar.infamy` also rises +2 for killing a ship, +1 for fleeing, +1 per five (rounded up) shady goods (Narcotics, Weapons) sold; at 20 and 60 it steps `ship_disposition` up a notch (a great standing offsets it). Status shows it. Black markets and the underworld quest (step C) will use it.
- The underworld (`underworld.odin`; new in the port): rough planets (`planet_is_rough`: faction Standards <= 42 or Authority <= 35; SIGMO never) have fixers at their star docks. `Avatar.quest` is a stage machine (`Quest_Stage`: None, Lead, Package, Goods, Prove, Proven, Connected) driven by one dock interaction, `Underworld_Contact`, whose label comes from `underworld_offer` (Ask Around -> Meet The Fixer [take a sealed `Package` item, kept from patrols] -> Hand Over The Package [+3 infamy] -> Deliver Contraband [10 Narcotics or Weapons, +5] -> win or flee a patrol fight (`quest_note_fight` from combat) -> Report In). Connecting (`underworld_connect`: +10 infamy, +100 jools) spawns one `Black_Market` actor on every rough planet's orbit and makes rough docks offer shady deliveries (`Mission.criminal`: three times the reward, destination another rough planet, completing earns infamy instead of reputation, counts as contraband to every patrol and is taken by a surrender). A black market (bump -> Trade In The Shadows -> `Market_Screen{black = true}`) trades any good, banned or not, buying at 105% of the market price and paying 115% plus 1% per 4 infamy (max +20%). Saves can reach about 400 KB on the densest galaxy (base64 in localStorage), so six dense slots approach browser limits.
- Standing and the run summary (`law.odin`, `Game_Over` in `play_screens.odin`; new in the port): a planet's faction charges you by your reputation with it (`standing_percent`: 90% at 25 or more, 115% at -10 or less) for items, goods you buy, refuel and oxygen, hull repair and shipyard fees (not for what they pay you, and not at black markets); at -50 or less its trading posts, shipyards and star docks answer only "Ask For Service" (`Interaction.Refused`, `actor_refuses_you`). Bumping an actor with a planet sets `Avatar.service_percent` (transient), which the dock and yard prices read (`service_price`). `Avatar.stats` (`Run_Stats`: peak jools, deliveries, kills, planets visited) feeds the end-of-run screen: Game Over and Abandon both show `Game_Over{abandoned}` with turns, jools, peak jools, deliveries, ships destroyed, planets visited, infamy and a score (`run_score`: peak/10 + 20 per delivery + 40 per kill + 10 per planet + 3 per infamy + turns/20).
- Fit check: `text_put` counts characters that fall off the 40 columns in the thread-local `text_clipped`; `fit_test.odin` draws every screen with the longest possible names and fails if anything is clipped. Keep new screens to 40 columns (label column 2 for long lists, or put the second part on its own line).
- Keys cross the boundary as an i32: printable ASCII as its char code, others per `game/keys.odin`; `web/game.js` must use the same numbers.

## Legacy .NET stack

All code is VB.NET under `src/`, one solution `src/src.sln`, SDK 10.0 (`net10.0` for the exe and test projects, `netstandard2.1` for libraries). 451 of ~490 tracked files are `.vb`.

```bash
dotnet build src/src.sln
dotnet test src/src.sln                                   # xunit.v3 + Shouldly
dotnet test src/FHOS.Model.Tests                          # one test project
dotnet test src/FHOS.Model.Tests --filter "FullyQualifiedName~ActorModel_should"   # one class / method
dotnet run --project src/FHOS/FHOS.vbproj                 # needs a real terminal (Spectre.Console, ReadKey)
```

`shippit.sh` publishes single-file self-contained binaries for linux-x64/win-x64/osx-x64 and `butler push`es them to itch.io, then commits. `ship.sh` is its html5 replacement; delete `shippit.sh` once the port is playable.

### Layering (dependencies point downward)

```
FHOS (exe, Program.vb) → FHOS.Presentation → FHOS.Model → FHOS.Persistence → FHOS.Data
                                  │               └─→ SPLORR.Game (RNG, maze gen, utilities)
                                  └─→ SPLORR.Presentation.Spectre → SPLORR.Presentation (IUIContext, Mood)
```

- **FHOS.Data**: plain serializable data records (`UniverseData` and `*Data` for Actor/Group/Item/Location/Map/Store). The whole game state is one `UniverseData` graph, serialized with System.Text.Json (this is the save format). Entities reference each other by integer id, not object reference.
- **FHOS.Persistence**: `I*` interfaces + internal classes that are thin *clients* over `UniverseData` + an entity id (`ItemDataClient`/`Item` pattern: look up by id in the universe dictionaries, delete by removing from them). Per-entity folders also hold sub-aspects (actor equipment, inventory, offers, prices, yokes). Interfaces are public; implementations are `Friend`, built via `FromId`.
- **FHOS.Model**: game rules over persistence (`UniverseModel` is the root; Actor/Avatar/Group/Item/Location models). `Initializer/` builds a new universe step by step (`IInitializer` + `Steps/`).
- **FHOS.Presentation**: the UI as a state machine. `IState` / `BaseState` / `BoardState`; each state's `Start` runs until it hands off to the next. Folders map to screens: `MainMenu`, `Embark` (new game/generate), `SaveState` (+ "Scum" variants), `InPlay` (neutral, tactical, trader, dialog, inventory, equipment, verbs), and `Grimoire/` which centralizes all user-facing strings (prompts, messages, choices, key names). Put new copy there, not inline.
- **SPLORR.Presentation**: UI abstraction (`IUIContext`: Choose/Confirm/Ask/Message/Write/ReadKey, tagged with a `Mood`). Presentation code talks only to this interface; `SPLORR.Presentation.Spectre` is the one implementation. This seam is where a browser/canvas front end plugs in.

Tests mirror the layers (`FHOS.Data.Tests`, `FHOS.Persistence.Tests`, `FHOS.Model.Tests`); files are named `<Type>_should.vb`.

### Gotchas

- `schema/ecs.sql` and `schema.db` are an old MariaDB/HeidiSQL entity-component schema dump; the current code does not use a database.
- Assets: `sources/originals` (fonts, tileset, `FHOS_*.mid` music) and `sources/inputs` are raw sources; `ss/` holds itch.io screenshots/cover/icon. `src/FHOS/SIGMO.png` is the splash image loaded at runtime from the working directory.
